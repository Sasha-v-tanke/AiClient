# Мессенджер для службы курьеров — краткое описание

## Суть проекта

Клиент-серверное приложение для оперативной коммуникации между курьерами и диспетчерами службы доставки. Работает одновременно как веб-приложение (React) и Android-приложение (Kotlin), подключённые к единому серверу.

## Что делает приложение

Диспетчер                          Курьер
    │                                  │
    ├── Создаёт заказ                  │
    ├── Назначает курьера ────────────>├── Получает уведомление
    │                                  ├── Забирает заказ (статус)
    │   Автоматически создаётся чат <──┤
    ├── Пишет инструкции ─────────────>├── Читает, отвечает
    │                                  ├── Отправляет геолокацию
    ├── Видит местоположение           ├── Обновляет статус доставки
    │                                  ├── Подтверждает доставку
    └── Видит "Доставлено" ✅          └──
## Три ключевые функции

| Функция | Описание |
|---------|----------|
| Мессенджер | Чаты в реальном времени (WebSocket), индикатор печати, прочтения |
| Управление заказами | Создание, назначение курьера, отслеживание статуса доставки |
| Геолокация | Курьер передаёт координаты, диспетчер видит на карте |

## Роли пользователей

- Курьер — получает заказы, обновляет статусы, общается с диспетчером
- Диспетчер — создаёт заказы, назначает курьеров, координирует
- Админ — полный доступ ко всему

## Технологии

Сервер:    Node.js + Express + MongoDB + Socket.IO
Веб:       React
Android:   Kotlin + Retrofit + Socket.IO
## Главная особенность — перекрёстная валидация моделей

Модель `DeliveryStatus` проверяет корректность модели `Order`:

Пример: курьер нажимает "Доставлено"
                    │
        DeliveryStatus (pre-save) проверяет:
        ✓ Заказ существует?
        ✓ Текущий статус = "in_transit"? (а не "created")
        ✓ Переход in_transit → delivered допустим?
        ✓ Курьер назначен на этот заказ?
        ✓ У курьера есть право менять статус?
                    │
        Всё ок → обновляет Order.status
        Ошибка → отклоняет с описанием причины
Это гарантирует, что заказ не может перескочить через этап (например, из "создан" сразу в "доставлен") и только уполномоченный пользователь может менять статус.
